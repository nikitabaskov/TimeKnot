# 03 — Граф и шов `handle_message` на фейковом LLM

**What to build:** Появляется главный шов приложения: функция принимает текст, идентификатор пользователя и текущий момент, возвращает ответ бота. Граф LangGraph собран и ветвится по интенту, но за модель отвечает подставной клиент — живой провайдер здесь не нужен.

Это фундамент для всех последующих тикетов: дальше они пишутся и тестируются, не касаясь сети.

**Blocked by:** 02 — Хранилище задач и пустой `/tasks`.

**Status:** ready-for-agent

- [ ] Pydantic-схема результата разбора содержит `intent` (`create_task` / `list_tasks` / `complete_task` / `smalltalk`) и поля задачи
- [ ] LLM-клиент описан протоколом; реализация в этом тикете — фейк со сценарными ответами
- [ ] Часы описаны протоколом; ни один тест не зависит от реального времени
- [ ] Граф LangGraph: узел разбора, conditional edge по `intent`, узлы-заглушки для каждой ветки
- [ ] Поля задачи читаются только при `intent = create_task` и игнорируются при остальных, даже если заполнены
- [ ] Шов `handle_message` вызывается из aiogram-хендлера и покрыт тестами на все четыре ветки
- [ ] Тест проверяет ответ бота и содержимое БД, а не имена узлов графа и порядок вызовов репозиториев

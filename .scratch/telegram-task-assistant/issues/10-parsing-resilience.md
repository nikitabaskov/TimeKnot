# 10 — Устойчивость разбора

**What to build:** Кривой ответ модели, недоступный провайдер или дата в прошлом больше не приводят к трейсбеку и молчанию. Владелец в каждом из случаев получает понятное сообщение и понимает, что делать дальше.

**Blocked by:** 04 — Живой разбор текста и создание задачи.

**Status:** ready-for-agent

- [ ] Невалидный ответ модели ловится как `ValidationError` и вызывает **ровно один** повтор с текстом ошибки, добавленным в промпт
- [ ] Второй провал подряд — честный отказ пользователю, задача не создаётся
- [ ] После валидации схемы `due_at` проверяется кодом: парсится, лежит в будущем, не дальше года вперёд
- [ ] Дата в прошлом отклоняется с объяснением, а не создаёт мёртвую запись
- [ ] `429`, таймаут и недоступность провайдера обрабатываются с экспоненциальной паузой; при исчерпании попыток пользователь получает сообщение о временной недоступности
- [ ] Ни один из этих путей не роняет хендлер и не оставляет частично записанную задачу
- [ ] Тесты: фейковый LLM отдаёт невалидный JSON, затем валидный; отдаёт невалидный дважды; бросает ошибку провайдера
